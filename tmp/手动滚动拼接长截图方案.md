# 手动滚动拼接长截图方案

## 1. 目标与范围

### 1.1 功能目标
- 在现有区域截图能力基础上，新增“手动滚动拼接长截图”能力。
- 用户手动滚动目标内容，程序持续采集所选区域并自动拼接为一张长图。
- 最终长图复用现有输出能力：保存、复制、贴图、OCR。

### 1.2 MVP 范围
- 仅支持纵向向下滚动。
- 仅支持手动滚动，不实现自动滚轮控制。
- 优先支持网页、文档、聊天记录等静态滚动内容。
- 允许用户在结束后直接导出长图，不在第一版中引入长图编辑器。

### 1.3 非目标
- 不保证对所有应用场景都稳定可用。
- 不处理视频、动画、频繁刷新内容的稳定拼接。
- 不做固定头部智能去重。
- 不做超长图无限内存扩展，仅做基础阈值保护。

## 2. 现有架构适配点

### 2.1 可复用模块
- `CaptureService`：已有显示器截图、区域裁切、位图导出能力。
- `OverlayWindowController`：已有选区交互与屏幕定位能力。
- `OverlayViewModel`：已有截图状态管理与确认动作回调能力。
- `CaptureService+Annotation`：现有合成导出逻辑可在后续长图编辑阶段继续复用。

### 2.2 新增长截图链路
- 单独增加长截图会话层，不直接侵入当前普通截图流程。
- 在菜单入口和选区交互层增加“长截图模式”。
- 增加连续采集服务、稳定帧判定器、拼接器、长图渲染器。

## 3. 总体架构

```text
用户选择“长截图”
    ↓
Overlay 进入选区模式
    ↓
用户框选滚动区域
    ↓
LongCaptureSession.start()
    ↓
ScrollingCaptureService 持续采集目标显示器
    ↓
按选区裁切出区域帧
    ↓
FrameStabilityAnalyzer 过滤滚动中间态
    ↓
LongScreenshotStitcher 做重叠匹配与新增内容拼接
    ↓
LongImageRenderer 生成最终 NSImage
    ↓
复用现有保存 / 复制 / Pin / OCR 输出链路
```

## 6. 服务层设计

### 6.1 ScrollingCaptureService

职责：
- 启动和停止连续屏幕采集。
- 将显示器帧按选区裁切成区域帧。
- 控制采样频率，避免无意义高频处理。
- 将结果回调给会话层，不直接参与拼接算法。

设计原则：
- 复用 `ScreenCaptureKit` 能力。
- 与现有 `CaptureService` 解耦，避免影响普通截图链路。
- 只做“持续产出合规区域帧”，不处理 UI 状态。

建议接口：

```swift
import AppKit
import CoreGraphics

protocol ScrollingCaptureServiceProtocol: AnyObject {
    func start(
        region: LongCaptureRegion,
        targetFPS: Int,
        minimumFrameInterval: TimeInterval,
        onFrame: @escaping (Result<CroppedFrame, Error>) -> Void
    ) async throws

    func pause()
    func resume()
    func stop() async
}
```

建议实现要点：
- 内部使用独立 `SCStream`，不要复用普通截图的一次性 continuation。
- 每帧从显示器图像中裁切 `LongCaptureRegion.rectInScreen`。
- 使用时间戳节流，默认 4~6 FPS 即可。
- 采集暂停时直接丢弃帧，不停止底层流，减少恢复成本。

建议内部属性：

```swift
final class ScrollingCaptureService: NSObject, ScrollingCaptureServiceProtocol {
    private var stream: SCStream?
    private var streamOutput: CaptureStreamOutput?
    private let outputQueue = DispatchQueue(label: "com.libreshot.longcapture.stream")
    private let processingQueue = DispatchQueue(label: "com.libreshot.longcapture.processing")

    private var isPaused = false
    private var frameIndex = 0
    private var lastEmitTimestamp: TimeInterval = 0
    private var currentRegion: LongCaptureRegion?
    private var onFrame: ((Result<CroppedFrame, Error>) -> Void)?
}
```

### 6.2 FrameStabilityAnalyzer

职责：
- 过滤滚动中的模糊帧和中间帧。
- 仅把“稳定帧”交给拼接器。

设计原则：
- 轻量实现，避免引入复杂视觉算法。
- 先用缩略图比较，降低 CPU 占用。

建议接口：

```swift
import CoreGraphics

protocol FrameStabilityAnalyzing {
    func evaluate(_ frame: CroppedFrame) -> StabilityDecision
    func reset()
}

enum StabilityDecision: Equatable {
    case bootstrap
    case unstable
    case stable(CroppedFrame)
}
```

建议实现策略：
- 将帧缩小到固定宽度，例如 240 px。
- 比较当前帧与上一帧缩略图差异。
- 若两次连续差异小于阈值，则认为当前画面已停稳。

建议内部属性：

```swift
final class FrameStabilityAnalyzer: FrameStabilityAnalyzing {
    private let differenceThreshold: CGFloat
    private let minimumStableCount: Int
    private var previousThumbnail: CGImage?
    private var stableCount: Int = 0
}
```

### 6.3 LongScreenshotStitcher

职责：
- 管理长截图拼接状态。
- 执行相邻帧重叠区域匹配。
- 决定当前帧是否接受，以及新增内容追加多少高度。
- 维护最终输出所需的拼接片段。

设计原则：
- 只处理算法和结果，不处理屏幕采集和 UI。
- 对外暴露确定性接口，便于单元测试。

建议接口：

```swift
import AppKit
import CoreGraphics

protocol LongScreenshotStitching {
    func append(frame: CroppedFrame) -> StitchResult
    func finalImage() -> NSImage?
    func reset()
}
```

建议内部结构：

```swift
struct StitchSegment {
    let image: CGImage
    let offsetY: Int
    let height: Int
}

final class LongScreenshotStitcher: LongScreenshotStitching {
    private let matcher: OverlapMatching
    private let renderer: LongImageRendering
    private let maximumOutputHeight: Int

    private var baseFrame: CGImage?
    private var previousAcceptedFrame: CGImage?
    private var segments: [StitchSegment] = []
    private var totalHeight: Int = 0
    private var acceptedFrameCount: Int = 0
}
```

核心规则：
- 第一张稳定帧直接作为基准帧。
- 后续帧只与“上一张已接受帧”做匹配。
- 匹配成功后，仅追加“当前帧的新增底部内容”。
- 若新增高度太小，视为无效帧。
- 超过最大高度阈值时拒绝继续追加，并返回错误原因。

### 6.4 OverlapMatcher

职责：
- 计算上一帧与当前帧的垂直重叠区域。
- 返回重叠高度与拼接起点。

设计原则：
- MVP 使用简化版模板匹配。
- 先在缩略图上匹配，再把结果映射回原图像素。

建议接口：

```swift
import CoreGraphics

protocol OverlapMatching {
    func match(previous: CGImage, current: CGImage) -> StitchMatch?
}
```

建议实现类：

```swift
final class OverlapMatcher: OverlapMatching {
    private let workingWidth: Int
    private let minOverlapHeight: Int
    private let maxOverlapHeight: Int
    private let confidenceThreshold: CGFloat
    private let horizontalInsetRatio: CGFloat
}
```

建议匹配策略：
- 将图像缩放到固定宽度，例如 320 px。
- 仅取中间 60% 宽度进行匹配，忽略边缘滚动条与阴影。
- 用上一帧底部区域与当前帧顶部区域做多候选重叠搜索。
- 采用灰度差绝对值均值作为误差指标。
- 选择误差最小结果，并在满足阈值时返回。

### 6.5 LongImageRenderer

职责：
- 将拼接片段数组渲染为最终长图。
- 控制色彩空间、位图格式与输出尺寸。

设计原则：
- 不在拼接过程中频繁重建整张长图。
- 完成时一次性输出，降低内存峰值。

建议接口：

```swift
import AppKit
import CoreGraphics

protocol LongImageRendering {
    func render(segments: [StitchSegment], canvasWidth: Int, canvasHeight: Int, logicalSize: CGSize) -> NSImage?
}
```

建议实现类：

```swift
final class LongImageRenderer: LongImageRendering {
    private let colorSpace = CGColorSpace(name: CGColorSpace.sRGB) ?? CGColorSpaceCreateDeviceRGB()
}
```

## 7. 会话与编排层设计

### 7.1 LongCaptureSession

职责：
- 作为长截图业务编排中心。
- 协调采集、稳定帧分析、拼接、UI 状态更新和最终导出。

设计原则：
- 不把长截图业务逻辑堆到 `AppDelegate` 或 `OverlayViewModel`。
- 对 UI 层暴露简单、明确、可观察的状态。

建议接口：

```swift
import AppKit
import Combine
import CoreGraphics

@MainActor
protocol LongCaptureSessionProtocol: AnyObject {
    var statusPublisher: AnyPublisher<LongCaptureStatus, Never> { get }
    var progressPublisher: AnyPublisher<LongCaptureProgress, Never> { get }

    func prepare(region: LongCaptureRegion)
    func start() async
    func pause()
    func resume()
    func finish() async -> NSImage?
    func cancel() async
}
```

建议实现类：

```swift
@MainActor
final class LongCaptureSession: LongCaptureSessionProtocol, ObservableObject {
    @Published private(set) var status: LongCaptureStatus = .ready
    @Published private(set) var progress: LongCaptureProgress = .init(
        frameCount: 0,
        acceptedFrameCount: 0,
        totalPixelHeight: 0,
        lastConfidence: 0,
        statusText: "准备开始"
    )

    private let captureService: ScrollingCaptureServiceProtocol
    private let stabilityAnalyzer: FrameStabilityAnalyzing
    private let stitcher: LongScreenshotStitching

    private var region: LongCaptureRegion?
    private var frameCount: Int = 0
}
```

核心处理流程：
- `prepare(region:)`：保存选区与显示器信息。
- `start()`：进入 `.capturing`，启动持续采集。
- 收到帧后先经过 `FrameStabilityAnalyzer`。
- 稳定帧进入 `LongScreenshotStitcher.append(frame:)`。
- 根据 `StitchResult` 更新进度文案和累计高度。
- `finish()`：停止采集，渲染最终长图并返回。
- `cancel()`：停止采集并清空缓存。

## 11. 状态机定义

### 11.1 用户交互状态机

```text
idle
  → selecting
  → longCaptureReady
  → longCapturing
  → longPaused
  → finishing
  → completed
  → idle
```

### 11.2 异常分支

```text
longCapturing
  → failed(匹配失败过多)
  → paused
  → 用户调整后继续
```

### 11.3 状态切换原则
- `ready`：选区已确定但尚未开始采集。
- `capturing`：正在连续采集并尝试拼接。
- `paused`：停止接收有效帧但会话仍存在。
- `finishing`：停止流并生成最终长图。
- `completed`：已成功输出长图。
- `failed`：发生不可恢复错误，允许取消或导出当前已拼接内容。

## 12. 关键算法约束

### 12.1 匹配区域约束
- 只对图像中间区域做匹配，忽略左右边缘。
- 匹配上一帧底部与当前帧顶部。
- 默认仅支持向下滚动，不处理回滚。

### 12.2 帧接受规则
- 第一帧稳定后直接接收。
- 新帧匹配失败则丢弃，不立即报错。
- 连续失败达到阈值后显示提示。
- 新增高度小于最小阈值时丢弃，防止微抖动误拼接。

### 12.3 内存保护规则
- 设定最大输出高度，例如 30000~50000 像素。
- 片段数组只存新增部分，不重复保存整个已拼接结果。
- 最终输出时统一渲染，避免每帧重建整张长图。

## 13. 错误模型建议

```swift
enum LongCaptureError: LocalizedError {
    case invalidRegion
    case permissionDenied
    case streamStartFailed
    case frameConversionFailed
    case overlapMatchFailed
    case outputTooLarge
    case emptyResult

    var errorDescription: String? {
        switch self {
        case .invalidRegion:
            return "长截图区域无效"
        case .permissionDenied:
            return "缺少屏幕录制权限"
        case .streamStartFailed:
            return "长截图采集启动失败"
        case .frameConversionFailed:
            return "截图帧转换失败"
        case .overlapMatchFailed:
            return "未能识别滚动重叠区域"
        case .outputTooLarge:
            return "长图过大，已超出安全限制"
        case .emptyResult:
            return "未生成有效长截图内容"
        }
    }
}
```

## 14. 与现有代码的集成建议

### 14.1 尽量不改动普通截图主链路
- 保持 `CaptureService.captureDisplayImage` 继续服务普通全屏与区域截图。
- 新增长截图服务时避免改动其现有一次性 continuation 机制。

### 14.2 优先在 Overlay 层分流模式
- 普通截图仍走现有 `confirmCopy / confirmSave / confirmPin / confirmOCR`。
- 长截图在完成选区后进入独立会话控制流程。

### 14.3 最终结果统一回到现有输出
- 长截图结果生成后，继续复用：
  - `saveImageWithFallback`
  - `copyToClipboard`
  - `PinnedImageWindowController`
  - `OCRService`

## 15. 分阶段开发建议

### 阶段一：骨架接入
- 增加菜单入口与长截图模式状态。
- 完成选区后进入长截图控制条。
- 连续采集并展示实时状态文案。

### 阶段二：最小拼接闭环
- 实现稳定帧过滤。
- 实现基础重叠匹配。
- 能生成第一版长图并保存。

### 阶段三：体验增强
- 暂停 / 恢复。
- 失败提示和滚动建议。
- 结果导出选项。

### 阶段四：稳定性优化
- 调整阈值。
- 处理重复内容区域。
- 优化高分屏与超长图内存占用。

## 17. 验收标准

- 能从菜单进入长截图模式。
- 能正常框选滚动区域并启动采集。

- 失败时有明确提示，不导致应用卡死或崩溃。

## 18. 总结

本方案采用“会话编排 + 连续采集 + 稳定帧过滤 + 相邻帧拼接 + 最终统一渲染”的设计，将长截图能力作为独立链路接入现有项目。这样可以最大程度复用当前截图、裁切、导出基础设施，同时将高风险逻辑隔离在独立模块中，便于后续逐步增强与测试。
