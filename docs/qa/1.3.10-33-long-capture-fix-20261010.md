# 1.3.10 build 33 长截图局部重绘修复与验收

日期：2026-10-10。状态：**第一轮代码与专项回归通过，新包已安装且录屏恢复；用户实际长图已成图；另有失败与真实颜色微扰需要继续修复，未最终交付**。本文对应新 build 33；r4 的历史失败保留在原记录中，不作为本包实际验收结果。

## 问题与修复范围

生产累计器可确定性复现：已成功连接的两帧长图之后，末帧只发生零位移的单像素或光标重绘，精确去重不再相等，而位移匹配只搜索正位移。该帧持续未匹配，完成时拒绝已有完整长图。此前两次现场失败没有逐帧像素，尚不能断言与此缺陷同因。

新逻辑先尝试原有正反向运动匹配，仅在两者都失败时判断严格的局部重绘：原始像素最多 256 处变化，包围盒宽高小于 64 像素；变化列左右 32 像素范围内，必须在至少三个纵向分区各有八个保持零位移的结构锚点。限制横向锚点避免远处静态侧栏掩盖稀疏内容的真实滚动。

此情形不新增片段、不移动前沿、不修改已连接的像素。真实缺帧、周期歧义、大范围变化仍报告失败。追加日志只记录未匹配状态变化、帧数、宽高，不记录图像或文字。

## 后续复查与真实帧诊断

复查又发现 build 33 的变化列左右 32px 锚点仍会借近侧栏误判稀疏真实 1px 运动。当前源码已收紧为只用实际变化列锚点并逐行查边缘，新增四个反例断言与真实文本光标正例；54/54 通过，Issue4、17/18 与帧像素回归通过。证据 `review-hardening/`；当前 CaptureService 哈希 `712ea1faacef98811ae9ac55804322986cedc4939407bb638a9e67cdd58eb57f`，**安装 build 33 未包含该加固**。尚未打新包，先排查实际失败。

独立公开窗口探针旧录制器首次 `--record` 在 CGS_REQUIRE_INIT 初始化断言退出 134；诊断工具增加 NSApplication 初始化后单帧录制成功，不激活窗口、不请求授权、不捕获桌面。随后只记录公开 fixture window 15338 的 760×800 正文像素，120 帧，用于 R4/build33/加固源码重放。窗口流不同于正式 display crop，不能替代安装验收。

重启前内存采样首样 footprint 36.0 MiB，进程历史峰值 121.9 MiB，真实保存后约 60 秒及末一分钟回落到 46.0 MiB。RSS 同时仍超过 100 MiB，二者口径不同。重启后长截图失败后约 47 MiB；成功长截图的内存仍未验证。详见 `dist/long-capture-redraw-fix-20261010/MEMORY-BUILD33.md`。
