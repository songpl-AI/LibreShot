# OCR 高驻留专项诊断（2026-10-03）

## 结论

完整应用已做 45 次实际公开文档 OCR，每次得到 207 字符并关闭结果窗口，没有识别错误。高驻留仍然存在；本样例没有按次数持续线性累积，不据此关闭 Issue #5，也没有达到约 10 MB 的目标。

应用识别操作对象和输入 NSImage 在隔离生命周期检查中已释放，仍存在一个 VNRecognizeTextRequest。纯生产识别路径、未创建结果窗口时，闲置增量可重复约 69–71 MiB。完整应用堆中可见大量 Espresso/TextRecognition 对象；第 5/15 次时均只有 1 个识别请求、1 个关闭的结果控制器及 70 个 CGImage，主要对象数量未随次数叠加。这支持系统识别运行时保留模型或分配池是主要首次增量来源的解释，但没有证明 Apple 内部缓存淘汰机制，完整应用非对象分配的全部归属仍未获得分配栈证据。

识别后调用 request.cancel() 没有改善。没有因此修改生产识别参数、降低精度或加入无效的清理调用。

## 实际完整应用

使用已授权的 Release 预览 `acf0a60`，PID 24364，macOS 26.5.2 / Apple Silicon；正式应用未替换，没有新增录屏授权。只框选已有公开验收文档正文，选区与上一轮一致，600×940 Retina 像素。自动保存保持关闭，未点击复制文本或翻译，没有申请语言包。

| 阶段 | Physical footprint（MiB） | 说明 |
| --- | ---: | --- |
| OCR 前 | 43.2 | 此进程已做过一次截图保存，非冷启动 |
| 首次 OCR 结果窗口打开 | 120.1 | 实际识别成功 |
| 第 5 次后闲置约 142 秒 | 120.3 | 结果窗口已关闭 |
| 第 15 次后闲置约 63 秒 | 150.5 | 阶段峰值 241.0 |
| 第 30 次后闲置约 148 秒 | 165.9 | 再次较晚采样仍为 165.9 |
| 第 45 次后闲置约 133 秒 | 140.3 | 本进程历史峰值 255.3 |

各次闲置时间不完全相同，不能将差值视为严格的泄漏速度；内存压力和框架回收会影响驻留。较小公开文字图不覆盖报告者 350 MB、大图、多屏或长期翻译场景。第 5/15 次的堆中 non-object 合计约 49.8/105.7 MB，说明仅看对象数量不够；应继续关注较大分配和分配池，不能宣布全部内存已归因。

## 可重跑诊断

```sh
# 生产识别路径：约 69–71 MiB 首次驻留增量，会以退出码 1 报诊断预算超限。
bash tests/run-ocr-residency-profile.sh in-process
# 同一 PNG 输入的主进程对照。
bash tests/run-ocr-residency-profile.sh in-process-png
# 完成后额外 cancel，没有改善，同样退出码 1。
bash tests/run-ocr-residency-profile.sh in-process-cancel
# 仅构建、布局并关闭真实结果视图，保留一个空的关闭控制器。
bash tests/run-ocr-residency-profile.sh window-only
# 每次识别后退出的诊断子进程。
bash tests/run-ocr-residency-profile.sh worker-parent
# sandbox 父进程 + sandbox/inherit 子进程，不含额外文件或录屏权限。
bash tests/run-ocr-sandbox-isolation-profile.sh
```

32 MiB 是区分这次明显驻留的诊断预算，不是产品内存承诺。脚本不应作为默认 CI 中必绿的性能测试；读值依赖当前系统。每种模式执行 5 次识别（window-only 为 5 次关窗），作用域释放后闲置 15 秒，并检查原图及应用识别操作的弱引用。请求即时仍存活不能作为泄漏断言，因此以闲置后弱引用计数及 footprint 综合判断。

| 对照 | 基线 / 闲置（MiB） | 闲置增量 | 结果 |
| --- | --- | ---: | --- |
| 原始内存图，在进程中识别 | 5.50 / 75.24 | 69.73 | 操作 0、请求 1，输入图片释放 |
| 相同模式第二次独立运行 | 5.55 / 74.58 | 69.03 | 复现高驻留 |
| 在进程中识别相同 PNG | 5.48 / 76.11 | 70.63 | 操作 0、请求 1，输入图片释放 |
| 识别完成后 cancel | 5.44 / 75.88 | 70.44 | 无明显改善 |
| 仅结果视图，关闭后保留控制器 | 5.44 / 22.53 | 17.09 | hosting view 已移除；不是全部 OCR 增量 |
| 退出子进程后父进程 | 5.56 / 13.66 | 8.09 | 子进程 5 次均已退出 |
| 实际沙盒父子进程 | 6.81 / 14.39 | 7.58 | 子进程 5 次均已退出，父进程预算通过 |

子进程仍有约 66–69 MiB 的操作后观测值；没有连续采样真实瞬时峰值，也未证明所有进程的合计峰值下降。父进程驻留改善不能当成完整应用已经修复。

同一 PNG 输入的进程内/沙盒子进程结果：12 行文字、置信度、归一化位置一致，最大位置差为 0。原始 NSImage 与 PNG 输入的一处文字框有差异，所以正式接入仍需验证输入转换与原图翻译；不能将同一 PNG 对照解释为所有格式、颜色空间均无变化。诊断 worker 当前只验证英文生成样例，中文由现有完整应用路径验收，尚非中文 worker 对照。

## 证据、限制与下一步

原始本机日志、vmmap、heap、输出对照 JSON 均在 `dist/ocr-residency-20261003/`，不入 Git。隔离生产服务 15 次 / 每批闲置 15 秒为 100.99、103.94、111.13 MiB，首末差 10.14 MiB，未超过旧增长预算，仍明显高于基线。

初始两批压力参数不满足已有脚本“至少三批”的断言，已按三批重跑；即时弱引用断言也会把完成队列尚未清理的请求当成失败，已改为闲置后的计数。两项属于诊断配置调整，不是生产崩溃修复。失败日志保留在 dist 供审计。

新增的三个入口均为明确标记的诊断工具；生产代码和已授权预览包保持原样，没有留下生产调试日志。测试临时图片、编译产物由脚本清理，子进程结束，不读取用户图片、剪贴板或屏幕内容。

可行的下一步是将准确识别移到按需退出的辅助进程，保留相同识别参数与结果数据，先接入开发预览再验收。具体接入范围、错误与取消测试见 [接入方案](../design/ocr-process-isolation-plan.md)。这属于 OCR 执行架构调整，不是移除窗口引用即可完成的小修复。
