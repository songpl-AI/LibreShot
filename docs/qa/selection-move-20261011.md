# 选区空白拖动与拖动中断修复

日期：2026-10-11。基线 `547a8ce`（build 43 安装和授权记录）。维护者已反馈上一轮属性调整无问题，新增反馈：选区只能从边缘移动，且移动中途可能停止。已明确选择保持绘制工具，切回“选择／移动”后从空白处移动选区。

## 诊断和交互

- 新建 `bash tests/run-selection-move-checks.sh`，调用生产 OverlayView 使用的拖动准入接口；先仅提取原有准入判断，再复现“跟随工具栏盖住原鼠标按下点”被拒绝，检查退出 133。空白启动检查对应生产 `canMoveSelection`。
- 原实现每次 changed／ended 都用移动后的工具栏区域重新检查原始按下点，可能在拖动途中返回，连结束清理也被跳过。改为一次按下确定归属，松手／会话重置时释放；始于工具栏的拖动仍排除。
- 原选择模式只在 translation 为零时启动移动。新接口使用真实 startLocation，即使首个回调已有位移也能启动。已开始的选区移动在后续 changed／ended 中优先完成，不在途中改为缩放或标注操作。
- 选择模式扩展到选区内部空白；标注可见内容、已选中对象的移动区域与控制点保持优先。绘制工具不变，切回选择模式后移动选区，不自动退出当前绘制工具。
- 移动限制在屏幕内，保持尺寸，标注同步平移；普通点击 5 点以内抖动不移动，实际拖动取消双击候选，即使拖回起点也不误完成。空白双击完成保留，选区边缘和控制点仍不能触发完成。
- 追加撤销检查，复现移动后的属性撤销把标注恢复至旧绝对坐标，检查退出 133。移动时平移撤销快照（含序号／效果包装操作），保持对象和历史记录的坐标系一致。
