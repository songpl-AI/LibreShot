## 独立 OCR 实验

实验仅存于 `codex/ocr-helper-experiment`，提交 `df6b719`，入口为该分支的 `tests/experiments/run-ocr-process-probe.sh`。说明、源码和四份原始 JSON 已提交；没有合入 Preview，也没有实现生产沙盒 XPC。

Apple Silicon / macOS 26.5.2 / Xcode 26.5。两轮各使用全新父进程，同一张 2400 × 1400 合成图，调用生产 `OCRService` 五次，保留图片并闲置 60 秒。helper 每次新建、返回文字与坐标后退出。两种模式均编码一次 PNG；helper 耗时含启动、解码、OCR、JSON 传输和退出。无录屏、私有图片、系统剪贴板或语言包下载。

每 20 ms 读取父进程及直接子进程的 `ri_phys_footprint`，合计峰值为同一采样时刻的相加值；可能漏掉更短的峰值。不包含完整应用编辑器、外部系统服务、翻译模型和进程外 GPU 分配，也不是能耗测量。

| 指标 | 进程内，第 1 / 2 轮 | 短生命周期 helper，第 1 / 2 轮 |
| --- | ---: | ---: |
| 父进程图片基线 | 19.6 / 19.6 MiB | 19.5 / 19.5 MiB |
| OCR 后父进程闲置 60 秒 | 92.3 / 92.8 MiB | 21.4 / 21.3 MiB |
| 父子进程合计采样峰值 | 125.9 / 118.7 MiB | 127.8 / 126.5 MiB |
| 首次 OCR | 932 / 567 ms | 702 / 690 ms |
| 后续 OCR 范围 | 406–458 / 382–418 ms | 700–729 / 712–738 ms |
| 初始 PNG 编码 | 26.7 / 26.6 ms | 27.6 / 29.0 ms |

两轮文字与坐标一致。无效图片、子进程异常退出、终止并回收卡住的子进程、故障后的再次识别均通过。取消测试使用刻意停滞的子进程，不代表已覆盖真实 Vision 执行期间的取消竞态。第一轮启动邻近构建和回归，首次延迟只作诊断；两轮也不足以构成统计性能结论。

结论：可继续独立验证 XPC 方案，但暂不接入生产。主进程识别后闲置减少约 71 MiB，合计采样峰值没有减少；第二轮重复识别增加约 0.3 秒。不能把此处的 21 MiB 当作完整应用占用，也不能与此前包含编辑器和剪贴板的约 108 MiB 样本直接比较，后台 10 MB 目标仍未达成。
