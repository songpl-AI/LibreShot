# LibreShot 1.3.1 (18) 本地授权弹窗复验

日期：2026-09-28。基于 [17 版实机截图](1.3.1-17-local.md)：灰色遮罩已修正，但 macOS 录屏授权弹窗与应用自己的错误弹窗叠在一起。

## 修正与验证

- 第一次调用系统录屏授权请求而仍未授权时，`ScreenCaptureAccess.content` 抛出 `permissionRequestPending`，应用不显示自己的模态错误；同一进程后续再触发时，继续使用已有的单次权限恢复指引。
- `bash tests/run-toolbar-checks.sh` 新增精确断言：第一次系统请求不能同时呈现应用错误弹窗。此断言在修正前失败、修正后通过。原有权限门控及截图、翻译和工具栏回归同时通过。
- `bash tests/run-overlay-permission-checks.sh` 通过，覆盖预览失败后的遮罩清理和过期预览竞态。
- `bash build_release.sh dist/LibreShot-1.3.1-18-issue7-permission-qa` 完成 ad-hoc Release 归档、签名检查、DMG 创建和映像校验。

## 实机权限恢复结果

- 用户用实体键盘触发截图时，系统设置中曾同时出现 `LibreShot Preview.app` 和两个同名 `LibreShot.app`。Preview 使用独立 bundle ID `com.allensong.LibreShot.Preview`；正式版的录屏与输入监控 TCC 记录虽然显示允许，但 `csreq` 仍包含 1.3.0 (15) 的 CDHash `1dc293edb909f75cfaa2d923b799e62cb90a6ae5`，不包含 18 版的 `2fc43c79701bb4a75e9ec99d4f57b61d47d01579`。
- 退出应用后，仅对 `com.allensong.LibreShot` 执行 `tccutil reset ScreenCapture` 和 `tccutil reset ListenEvent`，并从系统设置的录屏列表移除残留的正式版旧项。未清除其他应用、Preview 的授权，也未删除本地构建或用户设置。
- 在系统设置中精确选择 `/Applications/LibreShot.app` 重新授予录屏与输入监控。两项系统 TCC 记录现在均为 `auth_value=2`，`csreq` 均包含 18 版 CDHash；应用从该路径重新启动。用户确认实体 `⌘⇧X` 可以正常截图，并在输入监控重新授权后反馈双击 Option 看起来也已恢复。
- 用户随后在区域截图中确认标注工具栏不再发灰，按钮显示与点击均正常。
