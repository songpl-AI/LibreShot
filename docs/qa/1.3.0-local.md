## 安装后权限故障

2026-09-21 用户反馈：已打开屏幕录制权限并尝试退出应用，仍报未获得权限。安装与启动通过不代表截图权限可用，本次交付遗漏了签名身份迁移的实际验证。

只读检查确认当前运行路径为 `/Applications/LibreShot.app/Contents/MacOS/LibreShot`。系统 `tccd` 在 20:16:52、20:19:47、20:20:14 和 20:20:20 重复报告：

```text
Failed to match existing code requirement for subject com.allensong.LibreShot and service kTCCServiceScreenCapture
```

日志中的已有授权要求旧 Apple Development 证书，而安装包的 designated requirement 是两个架构的 ad-hoc cdhash；与当前 `codesign -d -r-` 输出一致。20:20 的权限开关修改事件之后仍出现同样的匹配失败。因此不能把开关开启当成此二进制已经获得授权，也不应绕过权限预检或反复重编译来掩盖问题。

最小恢复方案：取得用户确认后退出 LibreShot，仅运行 `tccutil reset ScreenCapture com.allensong.LibreShot` 清除这一应用的旧录屏授权，再由用户为 `/Applications/LibreShot.app` 重新授权并重启。不得重置所有应用、直接编辑 TCC 数据库、关闭安全检查或由代理自动授予录屏权限。

用户明确回复“允许”后，已通过应用菜单退出 LibreShot，确认进程结束，再执行上述单应用命令，返回 `Successfully reset ScreenCapture approval status for com.allensong.LibreShot`。已重新启动 `/Applications/LibreShot.app` 并确认原有保存设置仍在。系统设置“录屏与系统录音”列表中旧 LibreShot 项已消失，另一个 LibreShot Preview 项仍保留；没有修改 Preview 或其他应用权限。当前停留在该系统设置页面，待用户手动添加并授权 `/Applications/LibreShot.app`、重新启动和验证真实截图；尚不能宣称截图故障已恢复。

后续日常升级应恢复稳定、有效的开发签名身份；ad-hoc 构建以二进制哈希标识，不能承诺下次重建继续沿用本次授权。
