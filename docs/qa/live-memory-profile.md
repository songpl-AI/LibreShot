# 真实操作内存复测

诊断包是独立的 `com.allensong.LibreShot.MemoryProfile` Debug 应用，不覆盖正式版，也不沿用正式版的屏幕录制授权。它本地临时签名、未启用 App Sandbox，只用于本机诊断，不能分发。绝对内存值不要直接与 Release 包相比，重点比较同一进程各阶段的增量和关窗后回落。

## 准备

1. `bash tests/build-live-memory-profile.sh`，记下输出的 `.app` 路径。
2. 退出正式版 LibreShot，避免菜单栏和快捷键冲突。
3. `bash tests/run-live-memory-profile.sh '/绝对路径/LibreShot Memory Profile.app'`。脚本启动诊断包，生成 `events.csv` 和 `processes.csv`。默认最多 90 轮，每轮采样应用、`translationd`、`TranslationAPISupportExtension` 的 `vmmap` physical footprint，轮次间至少间隔 5 秒。完成操作后退出诊断包，采样便自动停止；事件文件在脚本结束时归档。
4. 如果 macOS 请求诊断包的屏幕录制权限，由用户在系统设置中授权，再退出并重新启动诊断包和采样脚本。不要替诊断包重置或修改正式版的 TCC 授权。

## 固定操作顺序

每步使用同一块不含隐私信息的文字页面（推荐在浏览器打开 `tests/fixtures/memory-profile.html`），记录开始时刻；关闭相关窗口后各停留至少 60 秒，不交叉进行下一步。

1. 空闲 60 秒。
2. 区域截图一次，复制并关闭；空闲 60 秒。
3. OCR 一次，关闭 OCR 结果窗；空闲 60 秒。
4. 再次 OCR，在结果窗内翻译，关闭结果窗；空闲 60 秒。
5. 区域截图后使用原图对照翻译，等待译图完成，关闭/清除翻译和遮罩；空闲 60 秒。
6. 长截图滚动约 10 到 15 帧，完成后关闭预览或编辑器；空闲 60 秒。
7. 重复第 3 至 6 步一次，观察关窗后的基线是否继续线性上升。

`events.csv` 仅含固定阶段名、时间戳、PID 和应用自身 footprint 字节数；关闭事件后会自动补记 1/5/15/60 秒的应用 footprint。不会写入截图、OCR 原文或译文。`processes.csv` 是系统进程的独立观测值，不应全部计入 LibreShot 独占内存。`vmmap` 采样不是连续峰值采集；若某阶段持续留存明显增长，再对该阶段用 Instruments Allocations 和 MallocStackLogging 定位分配栈。测试完应退出诊断包，再启动正式版。

## 首次启动联调

2026-09-26 的首次持续采样保存在 `dist/memory-run-20260926-135014/`。诊断版打开设置页、未执行截图业务时，87 次 `vmmap` 采样的首末值为 17.1 MiB 和 45.8 MiB；事件文件只有 `app_launched`。另一次 `dist/memory-run-20260926-141551/` 也只有启动事件：脚本 `open -n` 创建的 PID 与 UI 操作绑定的进程不同，不能当业务采样。做 UI 自动化时必须核对操作进程 PID 与事件文件 PID 一致。

## 真实操作初测

获录屏授权后的同一诊断进程 PID 37035 的阶段记录在 `dist/memory-profile-cua-20260926-events.csv`，进程采样在 `dist/memory-profile-cua-20260926-processes.csv` 和 `dist/memory-profile-long-20260926-processes.csv`。测试关闭了诊断版的自动保存，不影响正式版设置。OCR、文本翻译、原图翻译使用设置页的公开文字；长截图框选快捷键列表。不同阶段的窗口/遮罩状态不完全相同，下列值是同进程阶段比较，不是统一冷启动基线。

| 阶段 | 操作中应用 footprint | 关闭后约 60 秒 |
| --- | ---: | ---: |
| 首次 OCR | 结果窗打开约 148.6 MiB | 约 84.7 MiB |
| OCR 结果窗内翻译 | 完成约 82.3 MiB | 已计入首次 OCR 关窗值 |
| 第二次 OCR | 结果窗打开约 153.4 MiB | 约 84.2 MiB |
| 原图对照翻译 | OCR 后约 154.1 MiB、译图后约 132.8 MiB | 清除并关闭选区后约 89.2 MiB |
| 长截图真实流 | 首帧事件约 180.0 MiB | 未能完成；见下文 |

两次 OCR 关窗后没有按次数线性增长；首次 OCR 后相对操作前留约 39 MiB，仍符合 Vision/ML 运行时缓存的假设，不能仅凭阶段值证明系统缓存归属。原图翻译本轮关闭后比开始前约高 5 MiB，需要重复轮次判断是否继续累加。翻译系统进程在此期间约为 `translationd` 60 MiB、`TranslationAPISupportExtension` 17 MiB，属于独立共享进程，不能全算作应用独占。

长截图是真实流路径的明确异常：只记录到首帧被接受，没有第十帧事件；持续采集期间 `vmmap` 的应用 physical footprint 从约 89 MiB 逐次上升，外部采样最高记录 27.9 GiB。为保护机器已主动退出诊断进程。这与离线 13 帧拼接器释放后接近基线的结果不同，排查重点是 ScreenCaptureKit 帧回调及待处理帧的生命周期，而非已接受片段的数量。该数值是 `vmmap` footprint，不应与 `ps` RSS 混为一谈。

已在流回调外包 `autoreleasepool`，让延迟稳定帧任务只读取最新待处理帧，不再由每个排队任务各自捕获整张图；进入待处理/匹配阶段的选区也已独立拷贝，避免保留整屏像素。Debug 加入第 10/100 个已处理帧事件和可经菜单触发的长截图完成/取消。离线拼接回归、截图内存回归、trace 检查及 Release 编译通过。

## 修补版真实流对照

重新授权精确的新构建后，以 PID 50848 在同一设置页和同尺寸选区重复两轮；事件在 `dist/memory-profile-final-20260926-events.csv`，第一轮外部样本在 `dist/memory-profile-final-20260926-processes.csv`。两轮均在约 10 秒内处理超过 100 个流帧，滚动列表后继续采集，并经诊断菜单完成。第一次完成进入编辑器，关闭后 `vmmap` 约 54 MiB；第二次因自身设置窗被 ScreenCaptureKit 排除、滚动画面无法接上而显示预期错误，清理后约 57 MiB。

| 真实流轮次 | 开始前应用 footprint | 采集中峰值 | 停止并清理后 |
| --- | ---: | ---: | ---: |
| 修补后第 1 次 | 约 44 MiB | `vmmap` peak 152.9 MiB | 约 54 MiB |
| 修补后第 2 次 | 约 54 MiB | `vmmap` peak 163.2 MiB | 约 57 MiB |

与旧版持续增长到 27.9 GiB 的同类流测试相比，修补版在约 90 秒的第一轮与随后第二轮中未见线性增长，已经验证了**空/重复画面持续采集的内存稳定性**。不能由此单独证明每处修改各贡献多少，也不能据此验收真实网页的多段滚动拼接；该页属于被排除的诊断应用自身，需另用外部可滚动页面测试已接受多帧后的输出与释放。记录这些数据时正式安装包尚未替换；后续安装状态见 [1.3.0 (13) 本地记录](1.3.0-13-local.md)。

## 第三轮外部页面尝试

同一 PID 又持续采集约 196 秒，流在 11 秒内处理超过 100 帧。应用事件 footprint 在第 100 帧约 157 MiB，采集结束后关闭编辑器并空闲约 60 秒为约 61 MiB；外部样本见 `dist/memory-profile-browser-20260926-processes.csv`。这再次支持流回调不再随时间无限累积，但**不是外部页面拼接通过**：虽然 Safari 测试页的滚动条从约 0.14 移至 0.36，完成后的截图显示实际选区内是 Codex 窗口，输出仍只有 1,200 x 970 像素，也未出现 `long_tenth_frame` 事件。macOS 台前调度把 Safari 留在另一个显示组，不能把浏览器的滚动算作捕获内容的变化。

测试页现为 48 个不同标题和段落，以排除重复内容造成的匹配歧义。下一步需要在同一可见显示组内做真实网页滚动，确认已接受多帧、最终高度大于单帧且关窗后 footprint 回落；在此之前，真实长图功能与其内存上限仍待人工验收。本轮未更改台前调度设置。

## 2026-09-27 两轮分阶段复测

正式版 1.3.0 (13) 的用户人工试用确认 OCR、文字翻译、原图对照翻译和长截图均可用，长图显示正常且结果窗口已关闭；其 15 分钟外部采样见 [本地候选包记录](1.3.0-13-local.md)。为了区分首次加载与重复操作的留存，随后暂退正式版，用此前已经授权的独立 Debug 诊断包对同一进程 PID 57510 顺序执行两轮。诊断包退出后已恢复 `/Applications/LibreShot.app`；没有改变正式版权限或设置。

固定框选诊断包设置页的公开文字。每项结束后关闭结果窗、清除译层或关闭编辑器，等待约 60 秒。下表由 `dist/memory-run-20260927-111510/events.csv` 的 `footprint_bytes / 1,048,576` 换算，单位统一为 MiB；`dist/memory-run-20260927-111510/processes.csv` 是约 16.4 分钟的外部间歇采样。

| 阶段 | 关闭后约 60 秒的应用 footprint |
| --- | ---: |
| 首次选区前，设置页已打开 | 34.7 MiB |
| 第一次 OCR | 71.1 MiB |
| 第一次 OCR 后文字翻译 | 75.3 MiB |
| 第一次原图对照翻译，清除译层与选区 | 75.9 MiB |
| 第一次长截图流，关闭编辑器 | 80.7 MiB |
| 第二次 OCR 后文字翻译 | 81.3 MiB |
| 第二次原图对照翻译，清除译层与选区 | 80.0 MiB |
| 第二次长截图流，关闭编辑器 | 80.3 MiB |

两轮长截图流均处理超过 100 个回调帧，随后正常停止并释放；第 100 帧的事件 footprint 分别约 172.0 和 173.6 MiB。外部 `vmmap` 采样峰值约 151.2 MiB，说明间歇采样漏掉了这些短时峰值。第二轮关窗后相对第一轮没有继续抬升，反而低约 0.4 MiB；OCR、翻译也没有重复出现首次加载时的数十 MiB 增量。这支持首次使用后框架/分配器常驻而非逐次累积的判断，但尚未用分配栈证明具体归属。

本次诊断长截图取的是被 ScreenCaptureKit 排除的设置窗，输出为单帧 980 x 330；它验证的是持续流回调及结束释放，**不是**真实滚动拼接。真实长图由用户在正式版目视确认正常，未程序化记录接受帧数和成图高度。原图翻译在这块较窄的中文设置区域切换到英文时提示 5 个译区过长或为空；这是该测试素材的排版结果，不作为通常页面翻译验收。
