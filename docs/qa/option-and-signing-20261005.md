日期：2026-10-05。当前对象：Preview 1.3.1 build 19，源码 `8330723`；正式应用未替换。

## 本轮已执行

- 原生打开快捷键设置，确认“双击 Option 启动区域截图”初始关闭。开启后出现输入监控缺失及授权后重启提示。
- 系统设置“输入监控”中，LibreShot Preview 为关闭，正式 LibreShot 为开启。没有更改正式应用的权限。
- 用户明确批准开启 Preview 输入监控。首次打开旧权限项并重启后，应用仍显示权限缺失；将权限项重新添加为 build 19 的确切路径并按系统提示重启后，系统开关为开启，应用缺失提示消失，功能设置保持开启。未更改正式应用权限，也未修改或重新签名应用。
- 尝试通过桌面工具发送左 Option，工具在投递前报 `keyPressIncludedNoNonModifierKeys`，不支持纯修饰键。因此不将模拟失败归因于应用功能，也不宣称实体左右按键验收通过；已请用户在 Finder / 浏览器前台快速双击左 Option 后反馈。
- 核对生产判定与已有回归：左右同侧两次完整短按触发；单击不触发；普通按键、鼠标及滚动中断序列。相关回归已随长截图修复的完整 Issue #4 检查通过，本次不重复整套测试。
- `security find-identity -v -p codesigning` 仍输出 `0 valid identities found`。不据此推断开发者账号资格或私钥是否存在，也不生成新证书或修改钥匙串。
- 更新 Preview 试用说明，纠正“OCR 辅助进程仍未接入”的过期描述。新增当前修复交付草稿，并同步到当前包目录的 `READ-ME.md` / `CURRENT-FIXES.md`；应用本体及 ZIP 未变，因此签名和 SHA-256 不变。

## 正式签名的准备条件

正式 Developer ID 交付需本机有可用的 Developer ID Application 签名身份（证书与对应私钥），然后运行现有 `build_release.sh --developer-id` 生成新的独立目录包并由 `scripts/verify_release_signing.sh` 检查应用和 OCR helper。该脚本明确将公证列为另一步；不能将签名通过写成公证完成。

当前没有有效身份，因此不启动注定失败的正式签名构建，不把 ad-hoc 包改称正式签名包。证书就绪后，仍需公证、最终包校验和正式身份的升级授权验收。公开发布与关闭 GitHub Issue尚未执行。
