# 1.1.1 翻译下载提示验收

环境：macOS 26.5.2，Apple Silicon。回归基线：`3225055`。收尾日期：2026-09-13。

## 实现与资源边界

- 交互入口改用 SwiftUI `.translationTask` 提供的会话，允许系统展示下载确认。原来的 `installedSource` 会话仅能使用已安装语言，保留给非交互检查。
- 初始配置为 nil。用户点击翻译才检测语言并启动请求；同语言文本直接返回，无需翻译会话。
- 每次请求递增配置版本。初版同语言取消后重试未弹窗，更新配置版本后，真实系统弹窗连续两次重试通过。
- 请求状态只保存文本、语言配置及 UUID，不持有 TranslationSession 或语言模型。完成时清空活动配置；关闭 OCR 窗口时移除 hosting view，终止其 SwiftUI 任务。
- 没有新增计时器或轮询。语言包文件和已确认的下载由系统管理，系统可能继续后台下载；不能承诺关闭窗口会撤销系统下载。
- 未做整机峰值内存的前后对照基准，不能把按需设计解释成零内存开销。

接口依据：[Apple TranslationSession](https://developer.apple.com/documentation/translation/translationsession)、[配置与重试](https://developer.apple.com/documentation/translation/translationsession/configuration)。

## 系统弹窗实测

`tests/TranslationUITestApp.swift` 是独立 SwiftUI 验收入口，复用生产 OCRResultView 和 TranslationService，不读取屏幕或用户文本。与这两个生产文件一起编译为本机签名的测试 App 后执行：

1. 默认简体中文，点击翻译；显示“你好，世界。 这是一个截图测试。”，没有下载提示。
2. 切换日语，点击翻译；显示系统“Download Languages to Translate”界面，含语言下载按钮和后台下载说明。
3. 不启动下载，点击 Done；回到 OCR 窗口，显示“已取消翻译，可再次点击翻译重试。”，按钮恢复可用。
4. 同语言连续两次重试，均重新出现系统下载界面。

以上步骤通过。没有为验收额外下载日语语言包，因此未验证新日语包的完整下载及下载后的日译结果。临时调试日志已从源码移除。
