## 本包修改与已有检查

普通截图使用每请求独立的取消/结果状态、局部 stream/output/scale 和串行生命周期 gate；首帧只复制一次，等待启动完成后停止，早取消和失败也进入清理。长截图的启动/停止串行化，避免流交叠与状态跨线程读写。已有 overlay、OCR 窗口释放和 Pinned 编码优化一并包含在本包。

候选目录中的日志确认 Release 构建、请求生命周期、BGRA 取帧、截图保存/剪贴板编码和窗口释放检查通过。确定性请求测试覆盖早取消、首帧早于启动完成、并发取帧只复制一次、失败清理和请求串行化。这些检查证明相应代码边界，不证明最终安装副本的系统权限、真实屏幕像素或持续操作内存。

本包默认保留 SDK queueDepth，未开启直接选区采集或切换到静态 API。[queueDepth 实验](queue-depth-validation-20261010.md) 的不同轮选区尺寸不完全相同，不能据此承诺节省几十 MiB。独立静态 API 探针尚无等价绘制/PNG 编码，低 footprint 也不能当成主应用的收益。

## 内存测量口径与目标

活动监视器默认“内存”、`ps RSS` 和 `vmmap Physical footprint` 分列。MiB 按 1,048,576 字节计算，活动监视器显示单位原样保留。本轮已取得同 PID、覆盖活动监视器读数时刻的 vmmap/CSV 配对；它支持本机本次默认列与 footprint 数值一致，不支持把该列称为 RSS，也不能倒推用户最初 100–122 MB 的具体场景原因。

最终 r4 的普通截图/保存也有百兆级峰值，完成后大图形块回落。30 次取消后稳定 footprint 约 48.5 MiB，活动监视器同阶段为 48.6 MB，仍未达到用户期望的 20–30 MB；本轮没有严格等像素的新旧包 A/B，不能宣称 r4 净降低多少内存，也不能承诺仅先释放 overlay 再裁剪就降低 80 MiB。

本包真实证据保存到 `dist/lifecycle-r4-validation-20261010/`，完整分配拆分见 [运行时内存分析](../../dist/lifecycle-r4-validation-20261010/RUNTIME-ANALYSIS.md)。根目录早期采样仅为 PID 45591 权限检查；`before-restart/` 为 PID 48937，`after-restart/` 为 PID 74368，`scroll-followup/` 和 `controlled-long-followup/` 记录两次长图失败及收尾；采样均已结束。两个保存 PNG 的公开页面不同，虽同为 500×350，也只作为功能验收，不能作严格像素或内存 A/B。

## 长图失败的诊断边界

两次真实尝试均已完成实际滚动和结束动作，但拼接失败，没有长图保存证据。第二次小步滚动也失败，不能简单归因为用户滚得太快。第一轮失败后对象释放与 allocator 延迟回收已有证据；这不能证明长截图功能通过。

独立离屏公开 fixture 探针使用生产 matcher/stitcher/accumulator 原样提取，295×760 窄选区在 17/72/156/174 像素步幅下均成功。故“窄选区或重复文字必然导致失败”不成立；真实输入帧、动态绘制和捕获时序仍待定位。探针只使用生成的公开图像，不替代真实 SCStream 验收，证据目录 `overlap-offscreen-probe/`。

另一个纯算法探针（`long-final-frame-probe/`，8 项断言通过）确认：已接受完整的两帧长图后，末帧只有单像素、零位移变化，也可能让累计器持续报未匹配并拒绝全部导出。这是可复现的独立缺陷机制，尚未证明是本次真实失败的根因。后续修复必须保留真实小滚动、漏帧及错误拼接的完整性检查，不能直接忽略末帧失败或降低所有阈值。最终 r4 binary 保持冻结；没有为本次诊断重新安装或再次刷新权限。

最终收尾配对 `14:47:37.916`：footprint 55.8 MiB、内核历史 peak 146.7 MiB、heap allocated 43.04 MiB。未识别出 overlay/SCStream/LongCaptureSession/累计器/拼接器实例，没有活跃的大像素 MALLOC_LARGE。相对普通取消后的 48.5 MiB，多约 7.27 MiB，主要落小堆与 empty 缓存，仍未取得分配栈。测试 sampler 已结束，公开滚动辅助程序已退出，正式 LibreShot 仍为原 PID 74368、原 CDHash；未重新换包。
