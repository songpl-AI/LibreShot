# LibreShot 1.3.34 build 90 闲置内存对照

2026-11-22。实测 /Applications/LibreShot.app，构建提交 `38d39db3d0d0b33738bb6032ce7c8103be7cc984`，主程序 SHA-256 `df6373203014a8cdb5e0325f4ffdc5dafc0e16a3ae3f202344b0cd6e464dcd4b`。M2 Pro，16 GiB，macOS 27.2.1 (26B131)，单屏 3024 × 1964，选区 2048 × 1280。屏幕内容为固定的公开英语测试窗口，翻译目标为简体中文。

## 自然回落

每项使用新启动的主进程，完成实际操作并关闭窗口，再观察约 302 秒。前值取操作前采样中位数，关窗读数取目标时间前 5 秒内采样中位数。单位为 MiB，指标为主进程 physical footprint。每项一轮，按原顺序运行，系统服务和 macOS 级别的缓存可以跨进程留存。

| 场景 | 操作前 | 关窗 1 分钟 | 关窗 2 分钟 | 关窗 5 分钟 | 5 分钟后快捷键至遮罩 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 只打开设置并关闭 | 17.2 | 37.4 | 37.4 | 37.3 | 307 ms |
| 普通截图并保存 | 17.0 | 39.6 | 39.6 | 39.6 | 232 ms |
| 只复制原图选区 | 17.2 | 39.4 | 39.5 | 39.5 | 331 ms |
| 单独译图 | 16.9 | 59.7 | 59.7 | 59.7 | 217 ms |
| 译图后复制选区 | 17.4 | 74.7 | 74.7 | 74.8 | 262 ms |

普通保存和单独复制在约 39.6 MiB 收敛。单独译图为 59.7 MiB，译图并复制为 74.8 MiB。关窗 1 分钟到 5 分钟，任一场景的差异小于 0.2 MiB。译图加复制的新进程结果低于此前同进程连续功能基线约 99.9 MiB。此差异提示进程前序状态会影响待机值。

两轮实际原图和译图复制均成功。临时调整自动保存和原图翻译工具显隐，原始配置在自然序列结束时已恢复。共享服务 `translationd` 在观测窗口约 59.4–60.3 MiB，系统翻译扩展约 16.8–16.9 MiB，均单列。

原始记录见 [自然回落汇总](../../dist/LibreShot-1.3.34-90-memory/qa/idle-study/natural-summary.json)。复测用证据目录的 `IdleStudy.swift` 和 `Launch.swift` 分别编译为同目录 `probe` 和 `launch`，再运行 `python3 run-study.py 新建证据目录`。脚本每轮从固定安装路径正常重启并在整轮结束恢复临时偏好。

本机同时在与工作树并列的 `LibreShot-memory-evidence/build-90/` 归档了完整 QA 目录、原 DMG、源码来源和安装记录。归档的 `QA-SHA256SUMS` 可逐文件验证原始采样、诊断日志、复测脚本与公开素材截图。

## 后续版本对比口径

- 常规待机基线取关窗后第 55–60 秒主进程 physical footprint 的中位数，单位为 MiB。上表同时保留第 2、5 分钟数据。若一分钟时占用仍在变化、重复操作后待机占用持续增加，或改动涉及延时释放，则延长观测到至少五分钟，并覆盖释放策略的触发时间。
- 每个场景启动一个新的主进程，走实际安装版的功能入口。前后版本使用同一台 Mac、同一显示配置、同一份 2048 × 1280 选区素材、同一翻译语言与相同功能设置。记录安装包版本、源码提交和主程序 SHA-256。另存此前[同进程连续使用基线](1.3.34-90-feature-memory-baseline.md)，供连续使用场景按原顺序复测。系统翻译服务和 OCR 辅助进程的占用单列。
- 下一轮用 build 90 和候选包对照译图后保存、译图后复制，普通保存和普通复制作为对照。每个版本的每个场景至少做三轮，保留逐轮原始采样。以各轮一分钟值的中位数计算减少量（旧值减新值）和降幅（减少量除以旧值），同时记录全程峰值、导出阶段峰值和下一次快捷键到遮罩的耗时。普通截图和译图都校验实际保存的图像与剪贴板读出的像素。

按上述口径完成的结果见 [build 90 和 build 91 对照](1.3.34-91-export-memory-comparison.md)。

## 关窗后的分配归因

Instruments CLI 使用 Allocations 与 VM Tracker 附加正式安装进程失败。随后用同一签名、同一安装路径重新启动，通过进程环境打开 MallocStackLogging lite 并采集 `vmmap`、`malloc_history` 及堆对象类型表。以下数值属于插桩诊断，由普通保存和译图后复制完成后约一分钟的快照得出。

| 诊断项目 | 普通保存 | 译图后复制 |
| --- | ---: | ---: |
| 主进程 physical footprint | 59.1 MiB | 90.3 MiB |
| DefaultPurgeableMallocZone 脏页 | 32 KiB | 24.9 MiB |
| IOSurface 区域 | 16 KiB 映射，0 驻留 | 16 KiB 映射，0 驻留 |

诊断快照中，译图复制的可丢弃分配区有约 67.5 MiB 分配容量，其中 24.9 MiB 为脏页。上述对照的主要差异集中在这个分配区。最大的几块分配在 `malloc_history` 中没有调用栈，暂时无法精确区分它们由译图合成、ImageIO 还是剪贴板交接分配。堆类型表里没有直接列出 `ImageTranslationModel` 或 `OverlayViewModel` 实例，仅见一个很小的系统翻译会话对象。实际复制走了 PNG 编码、再解码 PNG 并编码 LZW TIFF 的路径，两种剪贴板格式都发布且与 AppKit 读取结果一致。

## 闲置清理实验

离屏探针使用独立新进程和相同的真实产品渲染、导出代码。每种方案三对交替运行，对比清理前后主进程 footprint 的降幅，并减去未清理对照在相同时段的自然变化。

| 测试 | 额外释放中位数 | 配对范围 |
| --- | ---: | ---: |
| 马赛克和模糊后清理 Core Image 缓存 | −0.02 MiB | −1.28 至 −0.02 MiB |
| 普通图片复制后请求分配器回收 | 0.00 MiB | 0.00 至 0.02 MiB |
| 译图渲染并复制后请求分配器回收 | 0.02 MiB | −0.05 至 3.47 MiB |

分配器在所有清理轮次都返回释放 0 字节。18 个进程的对应 PNG 校验一致。马赛克和模糊下次渲染的中位数在对照组为 34.7 ms，清理组为 35.8 ms。这个数字来自离屏渲染，安装版下一次热键至遮罩的基线见自然回落表。两种清理策略均未显示可重复的长期收益，生产安装包继续使用已验收的 build 90。

## 译图导出路径补充对照

进一步用各自新进程完成真实译图，再分别做纯保存或纯复制，两轮均关闭窗口约 66 秒。

| 场景 | 操作前 | 关窗约 60 秒 |
| --- | ---: | ---: |
| 译图后保存 | 17.3 MiB | 73.9 MiB |
| 译图后复制复测 | 16.9 MiB | 70.6 MiB |

两轮导出的 PNG 字节相同。复制轮确认 PNG 和 TIFF 都由应用正式发布，TIFF 为 LZW，AppKit 读出的像素一致。两条导出路径都有约 70 MiB 的一分钟占用，说明额外驻留在仅保存时也能出现。两条路径共用的译图导出准备是进一步缩小范围的切入点。其中现有代码先把译图合成回整屏，再裁成目标选区。这个环节仍需与实机关窗后的驻留做因果对照。

离屏原型验证了直接合成选区。对 3024 × 1964、4K、5K 三种底图，固定 2048 × 1280 选区，分别覆盖 sRGB、Display P3、不透明和带透明度。72 个独立进程，36 对合成结果像素哈希相同。当前屏幕尺寸对应离屏合成阶段峰值降低 20.5–23.1 MiB。这个探针直接复用生产译图渲染和整屏替换函数，验证的是整屏与选区合成环节，仍需覆盖实际导出入口、选区几何边界和安装版关窗后的占用。
