# 长截图约 120 帧失败调查

2026-10-03，用户报告浮条计数达到约 120 帧后失败。附件提示“有滚动画面未能接上，本次未生成完整长截图”，背景同时有 macOS“按键接收”授权弹窗。120 指浮条帧数，不是测试目录第 120 个文件。

## 已取得证据

- 提示来自 `LongCaptureError.incompleteCapture`：累计器最后仍存在未匹配帧时拒绝生成完整图，不是固定帧数限制。
- 实际生产 `LongCaptureFrameAccumulator` + 拼接器独立探针，480×480 像素编号行形状样例，每帧下移 17 像素：119、120、121、160 帧都没有匹配警告，最终高度分别为 2486、2503、2520、3183，符合预期。
- 执行：`LIBRESHOT_OPTIMIZE=1 bash tests/compile-checks.sh dist/long-capture-diagnosis-20261003/frame-probe dist/long-capture-diagnosis-20261003/LongFrameProbe.swift`，然后执行该探针。结果见忽略目录 `dist/long-capture-diagnosis-20261003/results.log`。
- 探针是诊断用合成输入，只排除这一样例上的固定 120 帧上限；它没有复现用户的真实屏幕序列，不能据此宣布问题修复或 Finder 验收通过。

## 2026-10-05：真实 Finder 像素复现与修复

从专用公共目录的原生区域截图取得 1938×1168 的编号行图像，保存为 `tests/fixtures/finder-numbered-rows.png`。裁出 1898×600 的连续视口，以 80 / 160 像素步长滚动并附上最后一帧。未修改的生产累计器稳定抛出与用户相同的 `incompleteCapture` 错误。进一步缩为偏移 20、340、548 的三帧仍失败；每个相邻视口都有充足重叠。

根因是去重器将画面缩为 96 像素宽，以平均灰度差小于 0.4 判定静止。Finder 重复行背景滚动后近似相同，编号的细微变化被平均掉；中间帧被丢弃，最终两帧的距离超过匹配范围。单独取消近似去重即可通过；单独增加匹配器采样宽度仍失败。因此本次只修改去重器：比较相同格式的实际像素，忽略行尾内存填充，保留所有真实变化。未匹配帧仍阻止输出，避免交付缺行图。

验证：

- 修复前完整回归退出 1，新增 Finder 80 / 160 像素滚动用例失败；修复后 `LIBRESHOT_OPTIMIZE=1 bash tests/run-issue4-checks.sh` 退出 0。
- 公共 Finder 输入在 4 / 80 / 160 像素步长下均完成；4 像素步长共 133 帧。最终图 1898×1128 与源图裁片逐像素相同，所有行完整且只出现一次。
- 最小三帧生产代码探针修复前退出 2，修复后退出 0，输出高度 1128 符合预期。
- 增加像素一致但行尾填充不同，以及只有一个像素变化的去重边界用例。
- 完整回归同时覆盖拼接、编辑、导出及跨进程 PNG/TIFF 剪贴板读取。原有 OCR 45 次实机验收无需因这次局部修改重跑。
