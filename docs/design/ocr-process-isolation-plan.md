# OCR 按需退出辅助进程接入方案

- 状态：诊断原型通过，尚未接入生产应用
- 依据：[2026-10-03 OCR 专项](../qa/ocr-residency-20261003.md)

## 目标与接口

把准确识别及系统识别模型的生命周期移到辅助进程。主应用继续截图、标注、显示 OCR 文本和原图翻译；识别完成后辅助进程退出，系统可回收该进程的模型与分配池。目标是降低识别后的主进程闲置增量，不能承诺全应用约 10 MB 或所有进程的合计峰值更低。

保留 `OCRService.recognizeText/recognizeRegions` 接口。请求传递实际像素尺寸的图片及协议版本、请求 ID；响应返回当前 OCRTextRegion 所需的 id/text/bounds/confidence/lineCount，保持左上角归一化坐标。辅助进程使用现有 accurate、语言纠正与 zh-Hans/en-US 配置，不降采样、不降低识别等级。

图片传输优先采用容器内 0600 临时文件或有边界的二进制管道。选型必须通过尺寸、透明度、颜色空间和识别文字位置对照，不能仅凭无损 PNG 可解码就宣称 OCR 位置完全无变化。响应具有大小上限与格式校验，不接受任意路径、命令或类反序列化。

## 生命周期与失败行为

- 保持当前串行识别语义，最多一个活动识别进程；排队请求可取消，避免积存整张图片。
- 任务取消时结束对应进程，清理临时数据，不向已关闭的界面提交旧结果。
- 完成或错误后必须等待并回收子进程；超时、异常退出、协议不匹配、缺失可执行文件都返回可读的错误。
- 不默默退回主进程 OCR，避免恢复原来的模型驻留行为。保持现有失败/取消界面反馈，截图权限不转交给 worker。
- 父应用退出时回收活动进程，异常退出后的临时文件按专用目录清理。

## 构建与权限

将辅助可执行文件纳入 Xcode 构建及本地预览/发布打包，分别生成 arm64/x86_64 并签名。辅助进程只使用 sandbox/inherit；不增加录屏、网络、照片、全盘或额外目录权限。正式签名/公证链路同时验证嵌套程序，不能把独立诊断脚本替代正式构建。

## 接入后的验收

1. 文本与位置：同一输入对照中英文、表格、Retina、透明/P3 图片；原图翻译沿用相同坐标及尺寸，编码转换差异须解释并检查回贴。
2. 生命周期：取消未启动与运行中的任务、连续并发入口、重复识别、父应用退出、worker 异常退出/缺失/坏响应，确认无挂起、无孤儿进程和临时图片泄漏。
3. 完整沙盒预览：同一组公开文档重复 OCR 45 次，每批采用相同闲置时长，测主进程和辅助进程，不能只报告主进程数值。
4. 常规回归：截图、PNG/TIFF 复制、自动保存、文字识别、文本翻译、原图翻译；ARM 实机，Intel 至少构建，实机和最低系统继续列为未验。

诊断原型已经证明沙盒中进程隔离可降低父进程闲置增量，生产取消、并发、打包及完整翻译链路尚未验证。以上完成前，Issue #5 保持未结案。
