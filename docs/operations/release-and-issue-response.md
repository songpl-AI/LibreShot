# 发布与 Issue 回复流程

适用于维护者已明确授权的 GitHub Release 发布及对应 Issue 回复。包与权限验收以 [安装与授权验收规范](install-and-permissions.md) 为准。

1. **固定发布包**：读取该版本 QA，核对版本、build、源码提交和 DMG SHA-256，确认最终安装副本同包重启前后截图保存通过。复用这一 DMG；应用重新构建或签名后须重新验收。文档提交可晚于构建源码，但须明确两者关系。
2. **更新文档**：更新中英文 README 的最新版本、CHANGELOG、版本说明和 QA。说明实际修复范围、验证证据、未覆盖环境及剩余需求；只将有实际证据的项目标为通过。
3. **推送与发布**：读取 GitHub 当前分支、标签和 Release 状态，正常快进推送代码与文档，标签指向包含构建源码的提交。上传原 DMG、SHA256SUMS 与安装授权规范。完成条件：Release 公开可见，资产齐全，重新下载的 DMG 校验值与验收包一致。
4. **回复 Issue**：仅在第 3 步通过后，按维护者授权回复对应 Issue，附版本链接、已完成行为、验证边界及未实现范围。部分实现或仍需报告者确认的 Issue 保持开放；较大需求留待专项处理。发送前核对已有评论，避免重试造成重复回复。
5. **记录结果**：将 Release、评论链接、下载校验和剩余 Issue 状态写入版本 QA，提交文档。完成条件：文档可追溯到发布产物，回复内容与实际实现一致。
