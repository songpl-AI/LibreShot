# LibreShot 新包安装与授权验收规范

维护日期：2026-10-05。适用于本机升级、开发试用包和 GitHub Release 候选。每次换包执行，结果写入独立的版本 QA 记录。此文件是操作规范；旧 QA 文件只提供历史证据。

## 交付标准

**安装完成不等于授权完成。只有最终安装路径的应用实际截图、保存成功，并在同一包重启后仍能截图，才能交给用户测试或宣称安装验收通过。** 输入监控与屏幕录制分别验收。用户提供密码或点击“允许”，仅代表完成系统操作，仍需检查结果。

当前默认沿用 GitHub 的 ad-hoc 签名分发，无需付费开发者账号。不同构建可能需要重新授权；规范保证发现和处理这种情况，不能保证 macOS 永远不弹授权。Developer ID / 公证是未来可选路线，不作为当前安装的前提。

## 固定脚本入口

本机打包、清理旧副本、安装与文件校验统一使用 [换包脚本流程](local-upgrade-script.md) 和 `scripts/upgrade_local.py`。脚本成功只表示文件安装完成，后续授权与实际验收仍按本规范执行。用户明确要求自行验证时，按该要求交接并记录待验，不能宣称实际验收通过。

## 1. 固定候选包

1. 确定版本、构建号、源码提交；本地未提交试用包额外保存源码差异与基线。使用 `build_release.sh --ad-hoc` 输出到新的独立目录。
2. 核验 DMG、`SHA256SUMS`、主应用和 OCR helper 的签名、架构及沙盒。使用仓库 `scripts/verify_release_signing.sh --allow-ad-hoc`；挂载后的应用再次核验。保留构建日志。
3. 后续安装、授权、验收使用这一份产物。应用本体一旦重编译、重签名或替换，即返回本步骤重新验收。单独更新外部文档不改变应用签名，但须说明文档与包的对应关系。

完成条件：记录包的绝对路径、SHA-256、版本、构建号、签名模式及源码来源，验证命令退出成功。

## 2. 退出并替换

1. 替换前记录现有设置：保存目录、自动保存、Option 开关、登录启动、工具顺序/隐藏项与默认工具；保留原偏好及书签。新进程若暂未加载原设置，先同包正常退出并重启复查，仍缺失则通过应用 UI 恢复原值，不删除容器或偏好。
2. 从应用菜单正常退出旧 LibreShot 及正在运行的 Preview/测试实例。检查实际进程路径，确认主应用和相关测试实例退出；不要仅根据窗口消失判断退出。
3. 正式本机安装固定使用 `/Applications/LibreShot.app`。Preview 保留独立名称和 bundle ID，权限与偏好独立，Preview 验收不能代替正式版验收。
4. 维护者已要求每次换包清理旧应用：确认进程退出和新候选完整后，将已安装副本及不再使用的旧同名应用副本按清单移入废纸篓，再安装新包；默认不累积可启动的旧 .app 备份。保留最新候选、必要公开测试 fixture、安装包、日志及源码；保留用户偏好、沙盒容器、保存目录和文件访问书签。回退使用保留的旧 DMG 或废纸篓，恢复后重新验收授权。
5. 核对安装副本与候选应用内容一致，再读取安装路径下的 Info.plist，检查版本、构建号、bundle ID、签名。正式身份目前为 `com.allensong.LibreShot`，实际值以最终包为准。
6. 后续始终从 Finder 的完整安装路径打开。不要从挂载卷、归档、备份或旧 Preview 启动。同名应用多个副本可能导致打开错误版本。

完成条件：实际主进程来自目标安装路径；版本/构建与候选一致，旧实例已退出，用户设置保留。没有设置窗口的菜单栏应用不等于打不开；从 Finder 再次打开可显示偏好设置。


## 3. 逐项检查并恢复授权

先启动安装副本进行检查，记录实际缺失项。下列权限分别处理；**某一项通过不能替代另一项**。

| 项目 | 使用场景 | 通过证据 |
| --- | --- | --- |
| 屏幕录制／录屏与系统录音 | 区域、全屏、长截图读取屏幕 | 最终应用出现含实际公开测试内容的遮罩，框选后成图成功 |
| 输入监控 | 已启用的双击 Option 手势 | 新版快捷键设置无缺失提示；实体双击 Option 出现遮罩，单独记录触发结果 |
| 保存目录访问 | 沙盒内保存 PNG | 实际文件写入成功、可解码，重启后原目录仍可用 |

### 屏幕录制与输入监控：每个缺失项执行同一恢复流程

1. 如果已有权限仍可实际使用，保留并进入验收；不要无故重置。系统列表开关为 on，但新版报缺失或实际操作失败，也按失效记录处理。
2. **先正常退出 LibreShot，再更新权限。** 进入系统设置 → 隐私与安全性 → 对应权限页；核对目标为正式版还是 Preview。
3. 移除对应旧 LibreShot 项；通过“+”重新添加 **当前安装副本的完整路径**，正式版为 `/Applications/LibreShot.app`。移除后观察列表，再添加；添加后观察条目和开关已开启，不能把“点击了打开按钮”当作成功。若选择面板仍显示旧文件身份或 URL 指向废纸篓，重新定位当前目录并核对完整 URL，必要时关闭后重新打开面板，不能提交旧副本。旧同名条目可能仍绑定旧签名/旧路径。
4. Touch ID、密码等系统身份验证交给用户完成。用户完成后，继续读取实际列表结果；不要重复要求已经批准的同一权限。只刷新本应用已有授权，不更改其他应用项目或全局安全保护。
5. 应用仍处于退出状态时，处理另一项失效权限。完成后从目标路径重新启动；系统要求“退出并重新打开”时必须实际执行。再次打开应用设置，检查输入监控提示和功能开关。
6. 立即执行下一节的实际截图验收。仍报录屏缺失时返回本小节核对屏幕录制项，不能仅修复输入监控就交付。

### 精确重置的后备流程

只有上述移除、精确添加、重启仍失败，且核对了安装路径与进程身份后，才考虑系统 `tccutil` 的单应用重置。先从安装副本读取并记录真实 bundle ID；只重置失败的服务和该 ID，保留其他应用权限。曾对 Preview 有效的命令是 `tccutil reset ScreenCapture com.allensong.LibreShot.Preview.Issue9`，它是历史实例，不能直接复制用于正式版。

正式版实际 ID 确认为 `com.allensong.LibreShot` 时，可按失败项单独使用：

```sh
tccutil reset ScreenCapture com.allensong.LibreShot
# 仅输入监控恢复失败时使用，记录系统命令结果：
tccutil reset ListenEvent com.allensong.LibreShot
```

记录命令退出状态；重置成功后重新添加当前路径、开启、重启并复验。系统不支持该服务或操作失败时记录原始错误，回到系统 UI 核对，不盲目循环。**禁止全局 `tccutil reset All`、修改 TCC 数据库、关闭 SIP/Gatekeeper、扩大应用权限或反复重签名来解决授权。**

### 保存目录

若截图已成图但写盘提示访问权限不足，通过应用的生产目录选择面板重新选择原保存目录，让应用获得文件访问书签，然后重试保存。不要把保存目录错误归为录屏错误，不删除容器或偏好，不增加全磁盘访问作为替代。

完成条件：每个需要的权限有单独结果。只开关开启、只提示消失、只成功重置，均仍未满足实际截图交付标准。

## 4. 最小实际验收（每包必做）

使用公开测试文字或专用测试窗口，避免保存私人桌面。先验证基础链路，再交给用户测试本次新功能。

1. 通过应用菜单“区域截图”启动，确认看到真实屏幕内容的遮罩；框选公开区域，绘制一笔标注，完成截图。
2. 保存到用户当前设置的目录，确认文件存在、可打开、尺寸及内容正确。检查复制出的图片内容；没有取得剪贴板证据时如实标为待验。
3. 正常退出，从同一安装路径重新启动；再次区域截图并保存，确认屏幕权限和保存目录可复用，没有再次授权提示。验收期间保持应用本体不变。
4. 用户原先启用双击 Option 时，确认设置仍启用且无输入监控缺失提示，并实测实体按键触发。桌面工具无法投递纯修饰键时，只请用户做这一项，保留“监听状态已验、实体触发待验”区别；原先关闭的功能维持关闭。
5. 对本次修改追加必要的功能验收。与变更无关且已通过的 OCR 长循环、长截图专项不重复；涉及 helper 打包、签名或权限改变时补 OCR 实际调用。

完成条件：至少两个成功的区域截图和保存证据，分别位于同包重启前后。Option/剪贴板等未实测项单列，不能写成全部通过。遇到 UI 绑定超时、空白窗口、ScreenCaptureKit 工具报错时，先重新识别应用/窗口；应用能否工作以实际证据判断。工具无法完成时说明“验收未完成”，不能以历史结果代替。

## 5. 记录、交付与回退

每包填写下方清单，附日志/公开截图路径。基础截图或保存失败时，状态写为“已安装，授权/验收未完成”，继续恢复；不要交给用户自行发现基础权限错误。只有第 4 节重启前后实际截图保存通过，才写“可以测试新功能”。发布仍以用户明确发布指令为准；发布资产须为已验收同一 DMG，附校验值、本规范及未覆盖环境说明。

| 检查项 | 结果（通过／失败／待验／不适用） | 证据或阻塞 |
| --- | --- | --- |
| 包路径、版本/build、源码、SHA-256 | | |
| DMG、主应用/helper 签名、安装内容一致 | | |

恢复仍失败时保留候选及证据，报告具体失败项；需要回退则退出新版、恢复备份应用，并对恢复包重新核对授权和实际截图。备份恢复也不能直接视为权限正常。

## 历史问题与依据

- [2026-10-03 保存授权](../qa/save-permission-20261003.md)：默认目录无沙盒访问授权；选择目录取得书签后保存恢复。同日旧 Preview 录屏路径刷新未恢复，精确 ScreenCapture 单应用重置后成功。
- [Option 与签名](../qa/option-and-signing-20261005.md)：旧输入监控项目即使开启也可能不匹配；重新添加确切新包路径并重启恢复。Preview 与正式权限分开；纯 Option 自动化受工具限制。
- [1.3.2 安装验收](../qa/1.3.2-20-package-20261005.md)：退出同名测试实例，更新正式录屏与输入监控记录，再通过真实截图、保存、OCR、同包重启。Finder reopen 解决菜单栏应用没有设置窗口的观察问题。
- [1.3.3 安装验收](../qa/1.3.3-21-package-20261005.md)：沿用精确路径更新两个权限，真实框选、编辑及保存成功。
- [1.3.4 本机试用](../qa/freehand-selection-20261005.md)：只确认输入监控提示消失就交给用户，随后用户实际截图报缺少屏幕录制权限。此为验收遗漏；随后已按本规范恢复录屏并完成重启前后截图保存；最终 build 23 结果见 [最终包验收](../qa/default-select-1.3.4-23-20261005.md)。
